AP LINKED METER FIX V5
======================

Revisión hecha contra el GitHub ACTUAL y la base Supabase ACTUAL.

PROBLEMA ENCONTRADO
-------------------
El backend actual de GitHub usa:

public_lighting_meters.meter_id

pero la base real NO tiene ese campo.

La base tiene:

public_lighting_meters.linked_meter_id

y ya está correctamente vinculado:
81 AP / 81 vinculados.

Además, las facturas históricas AP ya fueron migradas al modelo general:
meters -> invoices -> invoice_measurements.

QUÉ CORRIGE ESTE ZIP
--------------------
1. Backend AP:
   - usa linked_meter_id
   - deja de intentar escribir meter_id
   - consulta invoices generales
   - devuelve meter_id al front como alias del linked_meter_id
   - calcula consumo, demanda y factor de potencia desde invoice_measurements
   - usa invoice_lines para detectar penalización COS

2. Front AP:
   - abre el MISMO InvoiceAnalysisPanel de Dependencias
   - mantiene:
       Demanda
       Importe
       Factor de potencia
       Tarifaria
   - botón: Volver a Alumbrado Público
   - no muestra editor de nombre/ubicación específico dentro del análisis AP

3. No requiere más cambios en Supabase.

LIMITACIÓN REAL DE LOS DATOS HISTÓRICOS
---------------------------------------
Las facturas AP antiguas fueron importadas originalmente desde
public_lighting_invoices. Muchas de esas filas no contenían demanda
ni factor de potencia.

Por eso:
- donde invoice_measurements tenga demanda, se mostrará;
- donde tenga power_factor o tangent_phi, se mostrará/calculará;
- donde históricamente no exista ese dato, se mostrará S/D.

Esto ya no es una limitación del diseño: es disponibilidad del dato histórico.
