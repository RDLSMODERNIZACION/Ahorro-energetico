AP COMO CLASIFICACIÓN DEL MEDIDOR GENERAL - V4
================================================

OBJETIVO
--------
Dejar de usar public_lighting_invoices como fuente del análisis.

Alumbrado Público pasa a ser una CLASIFICACIÓN:
public_lighting_meters.meter_id -> meters.id

A partir de ahí AP usa EXACTAMENTE las mismas:
- invoices
- invoice_measurements
- invoice_lines

que Dependencias.

RESULTADO
---------
El análisis individual de AP abre el MISMO InvoiceAnalysisPanel
que una Dependencia, con datos reales de:

- Demanda
- Importe
- Factor de potencia
- Tarifaria
- Potencia contratada
- Conceptos facturados
- Mediciones
- Histórico

La tabla public_lighting_invoices NO se elimina.
Queda como histórico/legacy por seguridad, pero deja de ser la fuente
del análisis AP.

PASO 1 - BASE DE DATOS
----------------------
Abrí Supabase > SQL Editor y ejecutá:

supabase/001_ap_como_clasificacion.sql

Ese SQL:
1. agrega public_lighting_meters.meter_id
2. crea FK hacia meters.id
3. intenta vincular primero por supply_number
4. luego por meter_number
5. al final muestra los AP que quedaron sin vincular

Si la consulta final devuelve filas, hay que revisar esos pocos casos
manualmente antes de considerar la migración 100% terminada.

PASO 2 - CÓDIGO
---------------
Desde la raíz de Ahorro-energetico:

.\APLICAR_AP_COMO_CLASIFICACION_V4.ps1

El script:
- hace backup
- reemplaza el router backend de AP
- reemplaza el panel frontend de AP
- asegura que page.tsx pase invoices/tariffSavings/epenOptimization

PASO 3 - PROBAR
---------------
Backend debe estar reiniciado/desplegado.

Frontend:
cd front
npm run dev

IMPORTANTE
----------
No se modificó GitHub automáticamente.
Este ZIP es para aplicar localmente.

La migración es deliberadamente conservadora:
NO borra public_lighting_invoices.
Cuando confirmemos que todo AP ya funciona desde invoices generales,
podemos decidir si la tabla legacy se conserva o se archiva.
