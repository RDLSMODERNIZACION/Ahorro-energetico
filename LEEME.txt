ANÁLISIS AP IGUAL A DEPENDENCIAS - V3
=====================================

Problema encontrado al revisar GitHub:
Alumbrado Público usa la tabla public_lighting_invoices.
El intento anterior buscaba esas facturas dentro del array normal "invoices".
Como los IDs pertenecen a tablas distintas, selectedInvoice quedaba NULL y
el código caía al componente viejo IndividualAnalysis.

Por eso visualmente seguías viendo:
Resumen / Consumo / Importe / Tarifa

Esta V3 elimina ese problema:
- Alumbrado Público SIEMPRE usa InvoiceAnalysisPanel.
- Es el MISMO componente visual que Dependencias.
- Pestañas:
  Demanda / Importe / Factor de potencia / Tarifaria
- Volver dice "Volver a Alumbrado Público".
- La tarifaria AP muestra su histórico real de tarifa.
- Dependencias conserva su análisis tarifario avanzado existente.
- No modifica GitHub directamente.
- No toca la base de datos.
- Crea backups automáticos.

LIMITACIÓN DE DATOS ACTUAL
--------------------------
El endpoint public_lighting/analysis hoy solo devuelve:
- consumo kWh
- importe
- tarifa
- número de factura
- histórico de esos datos

No devuelve demanda máxima ni factor de potencia.
Por eso esas dos vistas quedan con 0 / S/D hasta incorporar esos datos
al backend de Alumbrado Público.

APLICAR
-------
Desde la raíz de Ahorro-energetico:

.\APLICAR_AP_IGUAL_DEPENDENCIAS_V3.ps1

Luego:

cd front
npm run dev
